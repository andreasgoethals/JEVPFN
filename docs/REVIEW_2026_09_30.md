## What is being converted

One task-aligned, deterministic question is evaluated against each text group. A group is
either one original text field or all of the row's text fields together. It is not a collection
of LLM-invented semantic attributes. This initial method produces task-relevant evidence
features, rather than a general-purpose text embedding.

The owner selected text-only requests in both modes: t per-column request slots and one joint
slot per row, before skipping empty inputs and cache reuse. No non-text features enter Jev.
Skip null/empty/whitespace-only inputs and store missing numeric features. A joint request uses
available fields and is skipped only when all fields are empty. With one available field,
per-column and joint reuse the same response.

The plan now has 40 table views (20 datasets times two modes), not 80 and not 40 numeric features.
The target is always separate. Metadata may include target/class names but never true row labels,
class frequencies, target summaries or model errors. See [the current feature design](FEATURE_CREATION.md).

## Exact output mechanism

The documented TypeSafe request has `model`, `state` and `questions`. The project previews that
body through `api_preview`; it has no live HTTP client. The pinned review reference is
`jev-1.13.0`. There is one question named `semantic` per intended request.

| Task | Jev primitive | Preserve | Proposed compact model input per text group |
|---|---|---|---|
| Binary | Noul: evidence favouring the chosen class over the other | `noul` in [0,1] | 1 probability |
| Multiclass | Choice: which permitted target class is supported? | All K probabilities and returned confidence | K probabilities |
| Regression | Score: ordered directional evidence for lower/higher target | Nine probabilities, returned confidence and expected direction | 1 expected directional score |

These mechanisms are documented by [Noul](https://docs.typesafe.ai/primitives/noul),
[Choice](https://docs.typesafe.ai/primitives/choice) and
[Score](https://docs.typesafe.ai/primitives/score). One multiclass request returns the whole
vector; K classes do not require K calls. Noul has no separate confidence field.

Binary orientation currently follows a stable mechanical class ordering. The class-to-column
mapping is saved explicitly. Choice uses stable IDs mapped back to the original typed labels.
No argmax reduction is necessary. Confidence is derived from the returned distribution; its
exact provider formula is not stated in the inspected [confidence documentation](https://docs.typesafe.ai/confidence).

Score accepts ordered descriptions and numbers them 0 through 8. We map these to -4 through +4.
The scalar is `sum((i - 4) * p[i] for i in range(9))`, equivalent to the provider score minus 4.
It is directional evidence, not a prediction in dollars, sales units or target standard deviations.
An expected score of zero can represent explicit neutral evidence or equal probability on
opposing extremes. Keeping the full vector lets experiment 3 distinguish those cases for free.

The nine intermediate descriptions are not ready for paid extraction: the current draft often
differs only by a numeric level marker. Jev evaluates descriptions, so those levels need clear,
independent meanings. Also decide what “relatively lower/higher” means without importing label
statistics. Preserve the agreed nine-level design while reviewing its wording. Jev probabilities
must not be assumed calibrated to the empirical target distribution of each dataset.

## TabPFN versions, text and Thinking

Both 3 and 3.5 have Thinking offerings. [The current model table](https://docs.priorlabs.ai/models)
distinguishes local Base models, hosted Plus text processing and hosted/enterprise Thinking.

| Version/access | Text route | Relevance here |
|---|---|---|
| Local TabPFN-3 | Older checkpoint defaults; text expansion can be enabled in the current package | Optional version comparison |
| Hosted TabPFN-3-Plus / 3-Thinking | Enhanced hosted text processing; Thinking spends more fit compute | Optional historical hosted comparison |
| Local TabPFN-3.5 | Built-in character n-gram TF-IDF + truncated SVD via `skrub.StringEncoder` | Proposed primary reproducible model |
| Hosted TabPFN-3.5-Plus / 3.5-Thinking | Proprietary enhanced text processing; Thinking adds fit computation | Optional stronger hosted comparison |

Local 3.5's text expansion produces up to 30 components per eligible field by default. Use
pandas `string` dtype; ordinary `object` strings are not expanded in package 9.0.0. Cardinality
and declared categorical columns also affect detection. The generic configuration class has
`TRANSFORM_TEXT=False`, but checkpoint settings override it: current documentation shows **True
for the 3.5 checkpoint**. Inspect the resolved checkpoint configuration in experiment 0.
See [preprocessing documentation](https://docs.priorlabs.ai/improving-performance/preprocessing)
and the pinned [TextTransformer implementation](https://github.com/PriorLabs/TabPFN/blob/v9.0.0/src/tabpfn/preprocessing/text.py).
This representation is learned on the training fold. It is not Jev-like semantic questioning.

The hosted text internals are proprietary in the inspected documentation; do not label them
as a specific embedding model or an LLM prompt pipeline without further evidence. The documented
Plus preprocessing limits include 2,500 characters per value and 50 million total text tokens,
so a fair full-text comparison needs an explicit length policy. Local 3.5 and hosted 3.5-Plus
must be reported as different baselines.

## Where each stage runs

Latest owner decision: design and previews, small local Jev tests, full local feature creation,
then experiment 0 and predictive experiments on VSC. This supersedes the earlier proposed order.
Jev performs inference remotely; a local GPU or VSC GPU does not accelerate its API service.
VSC modelling only needs immutable features and raw non-text data, not ongoing Jev connectivity.

Compute-node outbound HTTPS is **not yet verified**. Public VSC documentation and the synced
library do not establish a universal outbound guarantee. The optional `--network` preflight
tests DNS/TLS/HTTP from a real allocation using one unauthenticated HEAD request; it makes no
inference POST. A returned HTTP error proves reachability, not authenticated inference access.
After that, an explicitly approved tiny call would test the full route. Neither step has run
on VSC yet. This check is unnecessary for the chosen local Jev workflow. Login-node access or
inbound SSH firewall rules do not answer this question.

Use CreditPFN's account `lp_verbekelab` and a separate Python 3.12 environment named JEVPFN.
wICE interactive CPU fits the small preflight; `gpu_a100_debug` fits a short full-A100 test.
Profile ordinary A100 inference before requesting Mindwell B200 resources. See
[the VSC guide](VSC.md) and [official wICE instructions](https://docs.vscentrum.be/leuven/wice_quick_start.html).
Keep the only paid cache off temporary scratch; maintain a tested backup, and transfer complete,
hash-verified feature artifacts to the native filesystem of the chosen compute cluster.
